# RB-005 钓鱼邮件上报与处置

| 项 | 内容 |
|---|---|
| Runbook ID | RB-005 |
| 版本 | v1.0 |
| 负责人 | 安全运营（SOC） |
| 最后演练 | 待定（建议每季度） |
| 默认级别 | **P3**（批量/已点击 **P2**） |
| 关联 | `../41-phishing/`、`../43-clickfix/`、`../08-email-header-injection/` |

## 1. 触发条件

- 用户通过「上报钓鱼」按钮提交邮件
- 邮件网关告警：恶意附件/链接、DMARC 失败激增
- 多用户收到相同可疑邮件
- 外部（客户/供应商）告知收到冒充我方的邮件
- 员工报告「点了链接/填了密码」

## 2. 分级与响应时限

| 情形 | 级别 | 首次响应 |
|---|---|---|
| 已有多人点击/输入凭据 | P2 | 30 分钟 |
| 批量投递（>50 人）但未点击 | P2 | 1 小时 |
| 单封、未点击 | P3 | 4 小时 |
| 涉及高管/财务且已点击 | **P1** | 15 分钟 |

## 3. 角色与职责

| 角色 | 职责 |
|---|---|
| SOC 分析员 | 分析邮件、判定、提取 IOC |
| 邮件管理员 | 隔离/撤回、封禁域名 |
| 终端/EDR | 检查点击者主机 |
| IAM | 重置受影响账号 |
| 客服/HR | 通知与答疑 |
| IC | 批量事件协调 |

## 4. 前置准备

- [ ] 一键上报按钮已部署（Outlook/Gmail 插件）
- [ ] 可批量搜索/撤回邮件
- [ ] 沙箱环境（URL/附件分析）
- [ ] 可封禁域名/URL/哈希（邮件网关、DNS、代理、WAF）
- [ ] 用户通知渠道（全员邮件/IM/公告）

## 5. 处置步骤

### Step 1 接收与初步判定（0–15 分钟）

```text
1. 收集原始邮件（.eml），不要转发（会丢头信息）
2. 看关键头：Return-Path、Received、Authentication-Results、Reply-To、Message-ID
3. 对比显示名与实际域名；检查同形字
4. 提取 URL 与附件哈希，提交沙箱（不上传含敏感信息的附件到公网）
5. 判定：恶意 / 可疑 / 正常（误报）
```

```bash
# 只读：查看邮件头（示例）
grep -E '^(From|Return-Path|Reply-To|Received|Authentication-Results|Message-ID):' sample.eml
# 提取 URL
grep -Eo 'https?://[^" ]+' sample.eml | sort -u
# 附件哈希
shasum -a 256 attachment.*
```

### Step 2 界定范围（15–45 分钟）

```text
1. 主题/发件人/URL 在邮件系统中全局搜索
2. 统计：投递数、打开数（如有）、点击数、提交凭据数
3. 查询代理/DNS 日志：谁访问了恶意域名
4. 查询 EDR：谁执行了附件/粘贴了命令（ClickFix）
5. 标记高风险人群：财务、高管、IT 管理员
```

```text
# M365 搜索示例（PowerShell）
Get-MailMessage -SearchQuery 'Subject:"发票逾期"' -ResultSize 1000
# Google Workspace：管理后台 → 报告 → 邮件日志搜索
```

### Step 3 遏制（30–60 分钟）

```text
1. 从所有收件箱撤回/隔离该邮件
2. 封禁 IOC：发件域名、URL、IP、附件哈希
3. 对点击者：
   - 强制改密 + 吊销会话（见 RB-002）
   - 检查邮箱转发规则、OAuth 授权
   - 终端扫描（附件/ClickFix 场景）
4. 若为仿冒我方域名：提交下架、加 DMARC、通知客户
```

```bash
# 封禁示例（⚠️ 双人确认）
# 防火墙/DNS 层
echo "0.0.0.0 evil-login.example" >> /etc/hosts   # 仅应急，优先 DNS 过滤
# 代理层
# 添加 blocklist: evil-login.example, evil-cdn.example
```

### Step 4 用户沟通

```text
1. 向受影响用户发送定向通知（不是全员，避免恐慌）
2. 若批量投递：发全员预警（含样张与识别要点）
3. 明确「已做什么」与「你需要做什么」
4. 提供上报渠道与咨询方式
```

### Step 5 根因与改进

```text
1. 为何绕过网关？（新域名、合法 CDN、二维码、附件加密）
2. DMARC 是否生效？是否有域未配置？
3. 员工为何点击？（演练/培训缺口）
4. 是否需要调整网关策略、增加相似域名告警
```

## 6. 验证标准

- [ ] 恶意邮件已从所有收件箱移除
- [ ] IOC 已在网关/代理/DNS/WAF 生效
- [ ] 点击者账号已改密、会话已吊销、无异常登录
- [ ] 终端无可疑进程/持久化（如涉及附件/ClickFix）
- [ ] 用户通知已发送，上报量恢复正常
- [ ] 无新增同类邮件（连续 24 小时）

## 7. 升级与通知

| 情形 | 动作 |
|---|---|
| 已输入凭据/OTP | 升级 RB-002，立即冻结会话 |
| 已执行命令/附件 | 升级 RB-006，隔离终端 |
| 涉及资金指令（BEC） | 升级 P1，通知财务冻结 |
| 大规模投递 | 升级 P1/P2，全员预警 |
| 仿冒我方域名 | 品牌/法务介入，提交下架 |

## 8. 沟通模板

```text
【安全提醒 · 钓鱼邮件】
我们检测到一封冒充 ____ 的钓鱼邮件，主题为「____」。
请勿点击其中的链接或打开附件；如已点击，请立即：
1. 断开网络并联系 IT
2. 修改相关账号密码
3. 留意异常登录与转账请求
举报方式：____
```

```text
【给上报者】
感谢上报！我们已确认该邮件为钓鱼并完成全网清理。
您无需进一步操作 / 请按以下步骤处理：____
```

## 9. 取证与保全

| 证据 | 说明 |
|---|---|
| 原始 .eml | 含完整头信息 |
| 邮件头分析 | SPF/DKIM/DMARC 结果、跳转链 |
| URL/附件样本 | 哈希 + 沙箱报告 |
| 点击日志 | 代理/DNS/邮件追踪 |
| 终端证据 | 下载文件、进程、持久化 |

> 样本可能含恶意代码，仅在隔离环境分析。

## 10. 恢复与复盘

- 恢复被隔离邮件（误报时）并说明
- 更新网关规则与检测签名
- 针对性培训点击者（不羞辱，重在教育）
- 统计指标：上报率、点击率、处置时长、误报率

## 11. 附录

```text
快速识别要点
- 发件域名与显示名不一致 / 同形字
- Reply-To 与 From 不同
- 紧急语气 + 要求点击/转账/提供 OTP
- 二维码替代链接
- 要求打开终端粘贴命令（ClickFix）
- 附件为 .html/.zip/.iso/.lnk
```
