# RB-002 账号接管（ATO）

| 项 | 内容 |
|---|---|
| Runbook ID | RB-002 |
| 版本 | v1.0 |
| 负责人 | 身份与访问管理（IAM）负责人 |
| 最后演练 | 待定（建议每季度） |
| 默认级别 | **P2**（管理员账号 **P1**） |
| 关联 | `../42-account-takeover/`、`../14-brute-force/`、`../17-jwt-vulnerabilities/` |

## 1. 触发条件

- 异地/不可能旅行登录告警（同一账号短时间内多国）
- 用户举报「收到不是我发起的登录通知 / 不是我操作的」
- MFA 被新增、替换或关闭
- 登录后立即改密、改邮箱、加 API Key、导出数据
- 批量外发邮件 / 社交账号发垃圾信息
- 凭据在泄露库或暗网出现
- 客服/同事收到该账号的异常请求

## 2. 分级与响应时限

| 情形 | 级别 | 首次响应 |
|---|---|---|
| 管理员/财务/高管账号 | P1 | 15 分钟 |
| 普通用户 + 已确认异常操作 | P2 | 30 分钟 |
| 仅泄露告警，无异常登录 | P3 | 2 小时 |

## 3. 角色与职责

| 角色 | 职责 |
|---|---|
| 值班工程师 | 冻结会话、初步核实 |
| IAM/系统管理员 | 重置凭据、吊销 Token、恢复账号 |
| 风控/财务 | 评估资金与交易影响 |
| 客服/HR | 联系用户核实身份 |
| 法务/DPO | 涉及数据泄露时介入 |
| IC | 协调与对外口径 |

## 4. 前置准备

- [ ] 可查询登录日志（IP、设备、地理位置、UA）
- [ ] 可强制登出全部会话（`tokenVersion` / 会话存储）
- [ ] 可撤销 OAuth 授权与 API Key
- [ ] 有用户身份核实的备用通道（登记手机/工号/主管）
- [ ] 知道该账号的权限与数据范围

## 5. 处置步骤

### Step 1 冻结（0–10 分钟）

```text
1. 立即冻结会话（不是先联系用户，先止血）
2. 保留登录日志（截图 + 导出）
3. 若为管理员，暂停其高权限角色
```

```sql
-- ⚠️ 双人确认：吊销该用户全部 Token
UPDATE users SET token_version = token_version + 1, updated_at = now() WHERE id = :uid;
DELETE FROM sessions WHERE user_id = :uid;
```

```bash
# 只读：查最近登录
# 应用日志示例
grep '"event":"auth.login"' /var/log/app/*.log | grep '"userId":1234' | tail -50
```

### Step 2 核实身份（10–30 分钟）

```text
1. 通过「登记渠道」联系用户：工号 + 主管确认，或回拨登记手机
2. 不要用账号内留存的联系方式（可能已被攻击者改掉）
3. 询问：最近是否收到可疑邮件/短信、是否点过链接、是否安装过软件
4. 确认是「本人异常」还是「被接管」
```

### Step 3 清除攻击者立足点

```text
1. 重置密码（强制下次登录修改）
2. 撤销全部 OAuth 第三方授权
3. 删除/重置 API Key、Access Token
4. 移除新增的 MFA 设备，恢复用户原设备（需核实）
5. 检查并删除：邮件转发规则、自动回复、签名劫持
6. 检查并恢复：绑定的邮箱/手机号、恢复邮箱、安全问题
7. 检查：委派邮箱、共享邮箱权限、日历共享
8. 检查：云盘共享链接、代码仓库 SSH Key、CI Token
```

```bash
# AWS 示例：禁用并删除可疑 AK
aws iam list-access-keys --user-name alice
aws iam update-access-key --user-name alice --access-key-id AKIA... --status Inactive
# ⚠️ 双人确认后删除
aws iam delete-access-key --user-name alice --access-key-id AKIA...
```

```bash
# Google Workspace / M365 思路（管理后台）
# - 查看并删除邮箱转发规则
# - 撤销 OAuth 应用授权
# - 重置 MFA 并强制重新注册
# - 查看最近 30 天审计日志
```

### Step 4 评估影响

```text
1. 攻击者做了什么？登录记录、操作审计、邮件发送、数据下载
2. 是否发起过转账/退款/改价/授权？→ 立即通知风控冻结
3. 是否导出/外发数据？→ 可能升级为 RB-003
4. 是否向联系人发送钓鱼？→ 通知收件人，见 RB-005
5. 是否创建了后门账号/密钥/定时任务？
```

### Step 5 恢复与加固

```text
1. 用户完成改密 + MFA 重新绑定
2. 强制使用抗钓鱼 MFA（Passkey），如条件允许
3. 恢复必要权限（按最小权限，不直接还原旧权限）
4. 开启登录通知，观察 7–30 天
5. 若密码在其他站点复用 → 提醒用户全部更换
```

### Step 6 通知与记录

- 通知用户：发生了什么、已做什么、需要他做什么
- 通知主管（管理员账号必须）
- 若涉及资金 → 风控/财务
- 若涉及个人信息 → DPO（RB-003）
- 工单记录：时间线、操作、证据位置

## 6. 验证标准

- [ ] 旧密码、旧 Token、旧会话全部失效（401）
- [ ] 攻击者新增的 MFA/邮箱/手机/转发规则已删除
- [ ] 无异常 OAuth 授权与 API Key
- [ ] 无异常登录（连续 72 小时）
- [ ] 用户可正常登录，权限正确
- [ ] 相关交易/数据操作已核查

## 7. 升级与通知

| 情形 | 动作 |
|---|---|
| 管理员/域账号 | 立即 P1，通知 CISO，检查横向 |
| 涉及资金 | 立即冻结交易，通知风控与财务负责人 |
| 涉及数据导出 | 升级 RB-003 |
| 批量账号异常 | 可能为撞库/供应链，升级 P1 并排查入口 |

## 8. 沟通模板

```text
【账号安全通知】
您好，我们检测到您的账号于 ____ 在 ____（地点/设备）有异常登录。
为保护您的账号，我们已：
1. 登出所有设备
2. 暂停部分敏感操作
3. 重置登录凭据
请您：
1. 通过官方入口重新设置密码（不少于 12 位，且不与其他站点重复）
2. 重新绑定 MFA
3. 检查是否有异常邮件转发或授权应用
如有疑问请联系：____
```

## 9. 取证与保全

| 证据 | 内容 |
|---|---|
| 登录日志 | 时间、IP、ASN、地理位置、设备指纹、结果 |
| 操作审计 | 改密、改邮箱、加 MFA、建 Key、导出 |
| 邮件日志 | 发件记录、转发规则变更 |
| 会话记录 | Session ID、创建/销毁时间 |
| 资金流水 | 相关交易与审批记录 |

> 导出后计算哈希，存只读位置；不要修改原始日志。

## 10. 恢复与复盘

```text
1. 根因：钓鱼？撞库？会话窃取？内部人员？
2. 检测为何未更早触发？规则是否缺失？
3. 流程缺口：MFA 是否可被轻易关闭？改邮箱是否需二次验证？
4. 输出改进项并回写知识库（42/41/43）
```

## 11. 附录

```text
快速检查清单
- 会话是否全部失效
- 密码是否已重置
- MFA 设备是否只剩用户本人
- 邮箱转发规则是否为空
- OAuth 授权是否已清理
- API Key / Token 是否已轮换
- 绑定手机/邮箱是否为用户本人
- 是否创建了新的管理员账号
```
