# RB-001 勒索软件事件

| 项 | 内容 |
|---|---|
| Runbook ID | RB-001 |
| 版本 | v1.0 |
| 负责人 | SOC Lead |
| 最后演练 | 待定（建议每半年） |
| 默认级别 | **P1 紧急** |
| 关联 | `../48-malware/`、`../51-insider-threat/` |

## 1. 触发条件

满足任一即启动：

- EDR/AV 告警：勒索软件家族、批量文件加密行为
- 文件被改扩展名（`.locked`、`.encrypted`、随机后缀）或出现勒索信
- 卷影副本/备份被删除（`vssadmin delete shadows`、`wbadmin delete`）
- 共享盘大量文件同时变更、用户报告「文件打不开」
- 服务器 CPU/磁盘 IO 突增 + 大量文件重命名
- 收到勒索邮件或勒索页面

## 2. 分级与响应时限

| 情形 | 级别 | 首次响应 |
|---|---|---|
| 已加密生产数据 / 备份受影响 / 多主机扩散 | P1 | 15 分钟 |
| 单台非关键终端，已隔离 | P2 | 30 分钟 |
| 仅检测到投递物，未执行 | P3 | 2 小时 |

## 3. 角色与职责

| 角色 | 职责 |
|---|---|
| Incident Commander（IC） | 统一指挥、决策、对外口径 |
| 取证分析 | 保全证据、定位入口与范围 |
| 系统/运维 | 隔离、恢复、重建 |
| 网络 | 封禁 C2、隔离网段 |
| 法务/DPO | 是否上报、赎金合规评估 |
| PR | 对内对外沟通 |
| 管理层 | 赎金、停服、对外披露决策 |

## 4. 前置准备（演练时确认）

- [ ] EDR 可远程隔离主机
- [ ] 资产清单与业务影响分级（BIA）
- [ ] 备份可恢复性已验证（最近一次恢复演练日期：______）
- [ ] 离线/不可变备份存在且未被挂载
- [ ] 应急账号（break-glass）可用且离线保管
- [ ] 联系人表已打印

## 5. 处置步骤

### Step 1 确认与遏制（0–15 分钟）

```text
1. 确认告警真实性（看进程树、文件变更、勒索信样本）
2. ⚠️ 双人确认后，隔离受影响主机（EDR 网络隔离，保持开机）
3. 若为共享盘/域内扩散：立即断开相关网段，禁用受影响账号
4. 不要关机、不要重启、不要格式化——内存与进程是重要证据
```

```bash
# 只读：快速确认主机异常（macOS/Linux）
ps aux | grep -Ei 'encrypt|ransom|\.locked' | grep -v grep
lsof -i -P -n | grep ESTABLISHED
find / -xdev -newermt '-2 hours' -type f -name '*.locked' 2>/dev/null | head
ls -la /tmp /var/tmp | head -50
```

### Step 2 保全证据（15–45 分钟）

```text
1. 记录时间线（首次告警、隔离时间、每步操作）
2. 采集易失数据：进程列表、网络连接、登录用户、剪贴板、内存镜像
3. 保留勒索信原文与哈希，不上传公网沙箱（可能含组织信息）
4. 导出 EDR 事件、系统日志、文件审计日志到独立只读存储
5. 计算哈希（sha256）并登记
```

```bash
# 只读
mkdir -p /cases/RB-001-$(date +%Y%m%d) && cd $_
ps aux > ps.txt; netstat -an > net.txt; who > who.txt
log show --last 6h > system.log 2>/dev/null
shasum -a 256 * > SHA256SUMS
```

### Step 3 评估范围（30–90 分钟）

```text
1. 哪些主机被加密？哪些仅被访问？哪些是「零号病人」？
2. 备份是否被删除/加密？离线副本是否完好？
3. 攻击者是否已窃取数据（双重勒索）？查外联与数据外带日志
4. 入口是什么？钓鱼/弱口令/VPN/暴露服务/供应链
5. 是否有持久化（服务、计划任务、账号、密钥）？
```

### Step 4 遏制扩散

```text
1. 封禁已知 C2 域名/IP（防火墙、DNS、代理）
2. 隔离整个受影响 VLAN/子网
3. 禁用被盗账号，轮换相关凭据（见 RB-007）
4. 暂停相关备份任务，防止「好备份被覆盖」
5. 若域控受影响，按最高级别处置（可能需重建域）
```

### Step 5 决策：清除/重建/恢复

| 选项 | 适用 | 风险 |
|---|---|---|
| 清除恶意软件 | 仅确认单点、无持久化、取证充分 | 残留后门风险高 |
| **重装/重建主机**（推荐） | 生产主机、管理员主机、域控 | 耗时，需恢复数据 |
| 从备份恢复 | 备份未被污染 | 可能恢复回旧漏洞版本 |
| 付赎金 | 由管理层+法务+执法决定 | 不保证解密、助长犯罪、可能违反制裁 |

> 建议：**生产环境一律重建**，不要相信「清理干净了」。

### Step 6 恢复

```text
1. 先恢复基础设施（网络、认证、监控），再恢复业务
2. 从离线/不可变备份恢复，恢复前扫描
3. 分批恢复，每批验证：功能、数据完整性、无异常外联
4. 恢复后强制全员改密 + 吊销会话（见 RB-007）
5. 加强监控至少 30 天
```

```bash
# 只读：验证备份完整性
restic check
restic snapshots
# 恢复演练（隔离环境）
restic restore latest --target /restore-test
```

### Step 7 通知

| 对象 | 时机 | 内容 |
|---|---|---|
| 管理层/CISO | 确认 P1 后 30 分钟内 | 影响、已采取措施、需决策事项 |
| 法务/DPO | 确认数据可能泄露后立即 | 数据类别、人数、是否需上报 |
| 监管 | 按属地法规时限 | 由法务决定 |
| 客户/用户 | 评估后 | 统一口径，避免恐慌 |
| 执法机关 | 建议尽早 | 报案回执可用于保险与合规 |
| 保险 | 按保单时限 | 保留所有费用凭证 |

### Step 8 复盘（5 个工作日内）

```text
1. 完整时间线（检测→响应→遏制→恢复）
2. 根因分析（入口、为何扩散、为何未早发现）
3. 改进项：补丁、分段、备份、EDR 规则、权限
4. 更新本 Runbook 与知识库
```

## 6. 验证标准

- [ ] 无新增加密文件（连续 24 小时）
- [ ] 无异常外联/C2 通信
- [ ] 备份恢复演练成功，数据完整
- [ ] 所有相关凭据已轮换，旧凭据失效
- [ ] 持久化项已清除（账号、服务、计划任务、密钥）
- [ ] 业务功能验证通过，监控无异常

## 7. 升级与通知

- 扩散到第二台主机 → 立即升级 P1 并通知 CISO
- 备份受影响 → 立即通知管理层与备份负责人
- 涉及个人信息 → 立即通知 DPO/法务（见 RB-003）
- 收到勒索威胁公开数据 → 启动 PR + 法务 + 执法

## 9. 取证与保全

| 证据 | 采集方式 | 保存要求 |
|---|---|---|
| 内存 | EDR/Avidump/LiME | 只读介质 + 哈希 |
| 磁盘 | 镜像（dd/FTK） | 原件封存 |
| 日志 | EDR/SIEM/系统日志 | 导出后只读 |
| 勒索信/样本 | 原样复制 | 不公开上传 |
| 网络流量 | PCAP/NetFlow | 保留 30 天+ |

## 10. 恢复与复盘

- 恢复顺序：身份/网络 → 核心业务 → 次要业务
- 恢复后 30 天加强监控（异常登录、外联、加密行为）
- 复盘输出：时间线、根因、损失、改进项、责任人、截止日期
