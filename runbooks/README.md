# 应急处置手册 Runbooks

面向「**已经出事**」的场景：把谁做、何时做、敲什么命令、怎么验证、何时升级写死，让值班人员在压力下也能一致执行。

> 与 `../` 下的 53 篇知识库互补：知识库回答「怎么防」，这里回答「中招了怎么办」。

## 使用方法

1. 告警触发后，先按下方**分级表**定级，再打开对应 Runbook。
2. 从「触发条件」确认是否匹配，排除误报。
3. 严格按「处置步骤」执行；**破坏性操作（删除、重装、封禁、轮换）必须双人确认**。
4. 每完成一步记录时间、执行人、结果（工单里留痕）。
5. 处置结束填写「复盘」并回写知识库。

## 分级与响应时限

| 级别 | 判定 | 首次响应 | 升级 | 示例 |
|---|---|---|---|---|
| **P1 紧急** | 业务中断 / 数据正在外泄 / 大面积失守 | 15 分钟 | 立即通知 CISO/CTO | 勒索软件、云账号失陷、大规模数据泄露 |
| **P2 高** | 单点失守 / 高价值账号被控 | 30 分钟 | 1 小时内通知安全负责人 | 管理员 ATO、恶意软件、DDoS |
| **P3 中** | 有限影响 / 需调查 | 2 小时 | 当日汇总 | 单用户钓鱼点击、证书即将过期 |
| **P4 低** | 疑似 / 信息类 | 1 个工作日 | 周报 | 误报、扫描告警 |

> 分级可上调不可下调；无法判断时按更高一级处理。

## 通用执行原则

| 原则 | 说明 |
|---|---|
| **先止血，再取证** | 断网/隔离优先，但**不要关机**（内存证据会丢） |
| **保全证据** | 日志、内存、磁盘镜像、聊天记录，计算哈希后存只读介质 |
| **双人确认** | 删除、重装、封禁、轮换密钥等不可逆操作需第二人复核 |
| **最小破坏** | 优先隔离而非删除；优先禁用而非销毁 |
| **单一指挥** | 指定 Incident Commander，避免多人同时操作 |
| **记录一切** | 时间线、命令、输出、决策理由，供复盘与合规 |
| **不擅自对外** | 对外沟通统一由 PR/法务出口，避免二次事故 |
| **不轻易付赎金** | 涉及勒索时由管理层 + 法务 + 执法机关决策 |

## 演练与维护

- **频率**：P1 类 Runbook 每半年桌面推演一次，每年至少一次实战演练。
- **责任人**：每篇指定 owner，变更后 5 个工作日内更新。
- **版本**：文首表格记录版本与最后演练日期。
- **复盘**：每次真实事件后 5 个工作日内更新 Runbook，并回写知识库。

## 文档规范

- 命令区分 **只读（安全）** 与 **破坏性（需确认）**，破坏性命令前有 `⚠️ 双人确认` 标记。
- 涉及云厂商的操作用 CLI 示例，同时给出控制台路径。
- 所有时间使用 UTC 记录，展示时再转本地时区。
